# AI 개발 규칙 문서 관리 가이드

<!-- 이 문서는 사람이 규칙 문서를 고치거나 늘릴 때 읽는다. AI 작업 지침이 아니므로 AGENTS.md 문서 지도에 넣지 않는다. -->

## 1. 목적

이 저장소(FixLog Automation)의 AI 개발 규칙 문서를 어떻게 구성하고 고치는지 정한다.
규칙은 이 저장소 전용이다. 다른 저장소와 맞출 필요 없이, 프로젝트에 맞지 않으면 고치거나 지운다.

- 어떤 AI 도구든 저장소 루트의 `AGENTS.md`를 먼저 읽고, 문서 지도를 따라 세부 문서를 읽는다.

### AI에게 개발을 요청하는 방법

- 작은 작업: AI가 목적·대상·완료 기준을 세 줄로 정리해 보여 주고 진행한다.
- 큰 작업(신규 화면·API·시나리오 단계, `schema.sql` 변경, 수정 파일 5개 초과): AI가 `docs/specs/`에 명세 초안(요구 + 구현 계획)을 만든다. 초안을 확인·수정하고 "개발 시작"이라고 하면 구현한다. AI가 명세 6장에 결과를 쓰면 직접 확인하고 "완료"라고 한다.
- 자세한 흐름은 `docs/specs/_template.md` 맨 위 주석을 따른다.

### 스킬 (Claude Code)

| 명령 | 하는 일 |
|------|--------|
| `/self-review` | 변경 파일이 규칙 문서와 명세를 지키는지 검사하고 리포트를 출력한다. 코드는 고치지 않는다 |
| `/commit-generate` | 변경을 나눠 커밋한다. `git/commit.md` "AI 커밋"이 "금지"면 메시지만 제안한다 |
| `/pr-generate` | push하고 PR을 만든다 |

사전 준비: git 저장소로 만든 뒤 `docs/ai/git/branch.md`, `commit.md`의 1장 설정을 채운다. 스킬은 이 값으로 기준 브랜치와 커밋 여부를 정한다.

## 2. 구성

```text
(저장소 루트)
├─ AGENTS.md                 ← 입구: 개요, 명령어, 금지사항, 문서 지도
├─ CLAUDE.md                 ← Claude Code 진입점 (@AGENTS.md)
├─ .claude/skills/           ← Claude Code 스킬 (commit-generate, pr-generate, self-review)
└─ docs/
   ├─ AI-GUIDE.md            ← 이 문서 (사람용)
   ├─ specs/                 ← 작업 명세 SPEC-작성일-영문제목.md (요구, 계획, 결과 기록)
   │  └─ _template.md        ← 작업 명세 템플릿
   └─ ai/
      ├─ architecture.md     ← 스택, 구조 원칙, 레이어 위치·책임, 요청 흐름, 외부 연동, 환경
      ├─ rules/
      │  ├─ common.md        ← 모든 코드 공통 규칙
      │  ├─ convention.md    ← 코딩 컨벤션 (Python, JavaScript)
      │  ├─ backend.md       ← 서버 코드 규칙
      │  ├─ sql.md           ← SQL 규칙
      │  ├─ frontend.md      ← 화면 코드 규칙
      │  └─ project.md       ← 공통 모듈, 수정 금지 영역, 그 밖의 프로젝트 규칙
      ├─ workflow.md         ← 작업 순서, 멈춤 조건, 검증, 보고 형식
      ├─ domain.md           ← 용어, 상태 코드, 업무 규칙, 테이블 의미
      └─ git/
         ├─ branch.md        ← 브랜치 종류·이름
         ├─ commit.md        ← 커밋 메시지 형식, AI 커밋 허용 여부
         └─ pull-request.md  ← PR 제목·본문 형식
```

## 3. 규칙 ID

| 접두사 | 파일 | 접두사 | 파일 |
|-------|------|-------|------|
| BAN | AGENTS.md 금지사항 | FE | rules/frontend.md |
| ARC | architecture.md | PRJ | rules/project.md |
| COM | rules/common.md | WF | workflow.md |
| BE | rules/backend.md | DOM | domain.md |
| SQL | rules/sql.md | CONV | rules/convention.md |
| GIT | git/branch.md, commit.md | | |

- 각 파일 1장의 기본 규칙은 001~099, 이 프로젝트 기술(FastAPI, Playwright, React)에 따른 추가 규칙은 101부터 쓴다. PRJ·DOM·CONV는 001부터 쓴다.
- 한 번 쓴 ID는 다른 규칙에 다시 쓰지 않는다. 규칙을 지우면 그 번호는 비워 둔다. 지금 비어 있는 번호: BE-006~008, COM-044, FE-007, SQL-101(2026-11-04, 이 프로젝트에 적용되지 않아 삭제)
- 다른 문서의 규칙을 언급할 때는 내용을 복사하지 않고 ID로 참조한다. 예: `(BAN-003)`. 규칙을 지우거나 바꾸면 그 ID를 참조하는 곳을 `grep -rn "ID" AGENTS.md docs .claude`로 찾아 함께 고친다.

## 4. 작성 원칙

1. **규칙은 `ID / 규칙 / 이유` 표로 쓴다.** 이유가 있어야 AI가 규칙에 딱 맞지 않는 경우를 판단하고, 사람이 나중에 규칙을 유지할지 판단할 수 있다.
2. **규칙 하나에는 행동 하나를 쓴다.** "A하고 B한다"가 서로 다른 행동이면 규칙을 나눈다.
3. **AI가 판단할 수 있게 조건과 행동을 쓴다.** 아래 표현은 쓰지 않는다.

   | 쓰지 않는 표현 | 바꿔 쓰는 방법 | 예 |
   |--------------|--------------|----|
   | 적절히, 알맞게 | 기준을 숫자나 목록으로 쓴다 | "적절히 나눈다" → "메서드가 50줄을 넘으면 나눈다" |
   | 깔끔하게, 보기 좋게 | 지킬 형식을 쓴다 | "깔끔하게 정리" → "같은 파일의 기존 들여쓰기에 맞춘다" |
   | 가능하면, 되도록 | 조건과 예외를 쓴다 | "가능하면 공통 함수 사용" → "3장 목록에 있으면 공통 함수를 쓴다" |
   | 필요시, 필요한 경우 | 어떤 경우인지 쓴다 | "필요시 승인" → "수정 파일이 5개를 넘으면 승인" |
   | 주의한다, 유의한다 | 할 일과 하지 않을 일을 쓴다 | "로그에 주의" → "비밀번호를 로그에 남기지 않는다" |
   | 등, 기타 (목록 끝) | 목록을 끝까지 쓰거나 판단 기준을 쓴다 | "개인정보 등" → "주민등록번호·카드번호·계좌번호" |

4. **한 내용은 한 곳에만 쓴다.** 같은 내용이 두 곳에 있으면 한쪽만 고쳐져 서로 달라진다. 6장 표로 쓸 곳을 정한다.
5. **예시는 저장소에 실제로 있는 파일 경로로 쓴다.** AI는 예시 파일을 본보기로 코드를 만든다.
6. **AGENTS.md는 80줄 이내로 유지한다.** 넘으면 내용을 `docs/ai/` 아래로 옮기고 문서 지도에 한 줄을 추가한다.
7. **이 프로젝트에 적용될 수 없는 규칙은 남겨 두지 않는다.** AI가 없는 기능(로그인 사용자, 파일 업로드)을 위해 코드를 만들거나 불필요하게 멈추게 된다.

## 5. 체크리스트

| # | 확인 항목 | 확인 방법 |
|---|----------|----------|
| 1 | 채우지 않은 자리가 없다 | `grep -rn "{{" AGENTS.md CLAUDE.md docs/ai` 결과가 git 설정(branch.md, commit.md 1장) 외에 0건 |
| 2 | 없는 규칙 ID를 참조하지 않는다 | 3장의 비어 있는 번호를 `grep -rn` 했을 때 이 문서 외에 0건 |
| 3 | 문서에 쓴 파일 경로가 실제로 있다 | architecture.md 레이어별 위치 표의 예시 파일 열어 보기 |
| 4 | AGENTS.md가 80줄 이내다 | `wc -l AGENTS.md` |
