# PR 규칙

<!-- 이 문서의 역할: PR 제목·본문 형식이다. 사람과 AI(pr-generate 스킬 포함)가 모두 따른다. -->

## 1. 설정

| 항목 | 값 |
|------|----|
| PR 생성 명령 | gh pr create |

## 2. 제목

`[type] 요약`. type은 commit.md 3장을 따른다. 커밋이 여러 개면 PR 전체의 주된 목적으로 쓴다.

## 3. 본문

명세 파일이 있으면 명세에서 옮겨 쓰고, 명세 파일 경로를 "참고"에 적는다. 해당 없는 항목은 "해당 없음"을 쓴다.

```markdown
## 작업 유형
- [ ] 기능 개발
- [ ] 버그 수정
- [ ] 리팩터링
- [ ] 기타 (문서·설정)
<!-- 하나만 체크한다 -->

## 요약
- 무엇을 해결하거나 추가했는지 한 줄 (명세 1장)

## 배경
- 왜 필요했는지 (명세 1장·2장 "현재")

## 변경 내용
<!-- 작업 유형에 맞는 묶음 하나만 남긴다 -->
- 기능 개발: 구현한 기능과 주요 흐름, 핵심 조건, 영향 범위 (명세 2장·5장)
- 버그 수정: 증상, 원인, 해결 방법, 재발 방지 (명세 2장 "현재")
- 리팩터링: 무엇을 왜 정리했는지, 변경 전후, 동작 변경 없음 확인 방법

## 화면 변경
- 변경 전후 설명 또는 스크린샷. 없으면 "해당 없음"

## 검증
- 실행한 검증과 결과 (workflow.md 4장 "검증", 명세 6장)
- 완료 기준 결과 (명세 3장 번호별)

## 참고
- 명세: docs/specs/SPEC-...md
- 리뷰할 때 볼 곳, 후속 작업
```
