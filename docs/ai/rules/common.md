# 공통 규칙

<!-- 이 문서의 역할: 모든 언어·레이어에 적용하는 규칙이다. 특정 레이어·기술에만 해당하는 규칙은 해당 rules 파일이나 rules/project.md에 쓴다. -->

## 1. 변경 범위

| ID | 규칙 | 이유 |
|----|------|------|
| COM-002 | 기존 파일을 수정할 때는 들여쓰기·이름 규칙·괄호 위치를 같은 파일의 기존 코드에 맞춘다. 새 파일은 convention.md를 따른다 | 한 파일 안에서 스타일이 섞이면 diff와 리뷰가 어려워진다 |
| COM-003 | 새 함수·유틸을 만들기 전에 같은 역할의 기존 코드를 검색하고, 있으면 그것을 쓴다 | 중복 구현은 한쪽만 고쳐지는 수정 누락을 만든다 |
| COM-004 | 쓰지 않게 된 코드는 주석 처리로 남기지 않고 삭제한다 | 이전 코드는 버전 관리 이력에 남는다 |
| COM-005 | 존재를 확인하지 않은 클래스·메서드·설정 키·테이블·컬럼을 쓰지 않는다. 코드 검색이나 문서로 확인한 뒤 쓴다 | 추측으로 만든 이름은 컴파일·실행 오류의 주요 원인이다 |
| COM-006 | 접속 주소·포트·파일 경로·외부 시스템 URL처럼 환경마다 다른 값은 설정에서 읽는다. 코드에 쓰지 않는다 | 환경을 옮길 때 코드를 고쳐야 하고, 운영 주소가 개발 코드에 섞인다 |
| COM-007 | 공통코드 값(상태·구분 코드)을 문자열·숫자로 직접 쓰지 않는다. domain.md "공통코드"나 기존 상수를 쓴다 | 코드 값이 바뀌면 직접 쓴 곳만 수정에서 빠진다 |

## 2. 주석

| ID | 규칙 | 이유 |
|----|------|------|
| COM-010 | 주석에는 코드만 보고 알 수 없는 이유(왜 이렇게 했는가)를 쓴다. 코드 동작을 그대로 옮긴 주석은 쓰지 않는다 | 동작을 옮긴 주석은 코드가 바뀌면 거짓이 된다 |
| COM-011 | TODO 주석은 `TODO(작성자, YYYY-MM-DD): 내용` 형식으로 쓴다 | 누가 언제 남겼는지 알아야 정리할 수 있다 |

## 3. 로그

| ID | 규칙 | 이유 |
|----|------|------|
| COM-020 | 디버그용 표준 출력(콘솔 출력, 스택트레이스 직접 출력)을 쓰지 않는다. 같은 레이어의 기존 코드가 쓰는 로거를 쓴다 | 로그 레벨 제어와 운영 로그 수집이 되지 않는다 |
| COM-021 | 비밀번호·로그인 토큰(`access_token`·`refresh_token`)을 로그·실행 기록·스크린샷 경로에 남기지 않는다. 계정 이메일은 마스킹해서만 보여 준다 | 로그 파일은 접근 통제가 약해 개인정보 유출 경로가 된다 |
| COM-022 | 예외를 로그로 남길 때 예외 객체를 로거 인자로 넘겨 스택트레이스를 남긴다 | 메시지만 남기면 원인 위치를 찾을 수 없다 |

## 4. 예외 처리

| ID | 규칙 | 이유 |
|----|------|------|
| COM-030 | catch 블록을 비워 두지 않는다. 로그를 남기거나 다시 던진다 | 오류가 조용히 사라지면 데이터가 틀어져도 알 수 없다 |
| COM-031 | 모든 예외를 받는 최상위 예외 타입으로 잡지 않는다. 예외: 최상위 공통 예외 처리기 | 처리할 수 없는 예외까지 삼키게 된다 |
| COM-032 | 사용자 화면에 스택트레이스·SQL·서버 내부 경로를 보여주지 않는다 | 공격자에게 시스템 구조를 알려준다 |
| COM-033 | 예외를 다른 예외로 바꿔 던질 때는 원래 예외를 원인으로 넘긴다 | 원인 예외가 빠지면 최초 발생 위치를 찾을 수 없다 |
| COM-034 | 파일·DB 연결·브라우저처럼 닫아야 하는 리소스는 예외가 나도 닫히는 구문(`with`, `async with`, `try`/`finally`)으로 닫는다 | 누수된 연결·파일 핸들은 시간이 지나면 서버를 멈춘다 |

## 5. 보안

| ID | 규칙 | 이유 |
|----|------|------|
| COM-040 | 서버 코드는 외부 입력(요청 파라미터, 요청 본문, CLI 인자)을 서버에서 검증한다. 화면 검증만으로 끝내지 않는다 | 화면 검증은 요청 변조로 우회된다 |
| COM-042 | 외부 입력으로 파일 경로를 만들 때는 결과 경로가 허용 디렉터리 안에 있는지 검사한다 | `../` 경로 조작으로 서버 파일이 노출된다 |
| COM-043 | 외부 입력으로 OS 명령을 만들어 실행하지 않는다. 불가피하면 허용 값 목록으로 검사한다 | 명령 삽입으로 서버 권한이 넘어간다 |

## 6. 파일 형식

| ID | 규칙 | 이유 |
|----|------|------|
| COM-050 | 기존 파일은 원래 인코딩을 유지한다. 새 파일은 같은 폴더의 기존 파일과 같은 인코딩으로 만든다 | 인코딩이 바뀌면 한글이 깨지고 diff가 파일 전체로 잡힌다 |
| COM-051 | 줄바꿈 문자(CRLF/LF)는 기존 파일과 같게 유지한다 | 줄바꿈이 바뀌면 diff가 파일 전체로 잡힌다 |

## 7. 자동 테스트 코드

검증 방법과 순서는 workflow.md 3장을 따른다.

| ID | 규칙 | 이유 |
|----|------|------|
| COM-060 | 자동 테스트 코드가 있는 모듈에서 버그를 고칠 때는 그 버그를 재현하는 테스트를 함께 추가한다 | 같은 버그가 다시 생기는 것을 막는다 |
| COM-061 | 기존 테스트의 기대값을 바꿀 때는 요구가 바뀐 근거를 보고에 쓴다 (BAN-006) | 기대값을 코드에 맞춰 고치면 테스트를 지운 것과 같다 |
