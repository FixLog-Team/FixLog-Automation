# 서버 코드 규칙

<!-- 이 문서의 역할: 요청 처리·업무 로직·데이터 접근 등 서버 코드 규칙이다. 레이어 이름은 architecture.md "레이어별 위치" 표의 "역할"을 쓴다. -->

## 1. 기본 규칙

| ID | 규칙 | 이유 |
|----|------|------|
| BE-001 | 요청 처리 레이어는 요청 값 읽기, 입력 검증, 업무 로직 호출, 응답 변환만 한다. 업무 로직과 데이터 접근 호출을 넣지 않는다 | 업무 로직이 요청 처리 계층에 흩어지면 재사용과 테스트를 할 수 없다 |
| BE-002 | 트랜잭션 경계는 업무 로직 레이어의 메서드다. 요청 처리·데이터 접근 레이어에서 트랜잭션을 시작하거나 커밋하지 않는다 | 트랜잭션 위치가 일정해야 부분 저장 사고를 막을 수 있다 |
| BE-003 | 여러 테이블을 저장하는 하나의 업무 처리는 업무 로직 메서드 하나의 트랜잭션 안에서 처리한다 | 중간 실패 시 일부만 저장되는 것을 막는다 |
| BE-004 | 데이터 접근 레이어는 쿼리 실행과 결과 매핑만 한다. 분기·계산 로직을 넣지 않는다 | 업무 로직이 데이터 접근 계층에 숨으면 찾을 수 없다 |
| BE-005 | 반복문 안에서 건별로 쿼리를 호출하지 않는다. 일괄 처리(batch, IN 조건, 다건 INSERT) 쿼리를 쓴다 | 건수에 비례해 DB 왕복이 늘어 응답이 느려진다 |
| BE-009 | 업무 오류(입력 오류, 상태 오류)는 2장의 업무 예외로 던진다. 오류 메시지는 2장의 메시지 방식으로 만든다 | 오류 처리 방식이 하나여야 화면 처리가 일정하다 |
| BE-010 | project.md "공통 모듈"에 있는 공개 메서드·함수의 시그니처를 바꾸지 않는다. 다른 동작이 필요하면 새 메서드를 추가하고 승인을 받는다 | 공통 모듈은 호출처가 많아 영향 범위를 확인하기 어렵다 |

## 2. 이 프로젝트의 서버 코드 방식

| 항목 | 이 프로젝트의 방식 | 위치(클래스·파일) |
|------|------------------|-----------------|
| 요청 처리 기반 클래스 | 없음. `create_app()` 안에 FastAPI 경로 함수를 정의한다 | `backend/app/main.py` |
| 공통 응답 형식 | 성공은 리소스 JSON 그대로, 오류는 FastAPI 기본 `{"detail": 문자열 또는 검증 오류 목록}` | `backend/app/main.py` |
| 업무 예외 | `ScenarioError`(시나리오 입력), `BatchAlreadyRunningError`(중복 실행), `StepFailure`(단계 실패) | `backend/app/automation/scenarios.py`, `backend/app/runner.py`, `backend/app/automation/steps.py` |
| 메시지 조회 | 해당 없음. 한국어 메시지를 예외 생성 시 직접 쓴다 | |
| 입력 검증 방식 | pydantic 모델(`RunOptions`, `ScenarioCreate`)과 FastAPI `Query` 제약 | `backend/app/config.py`, `backend/app/main.py` |
| 트랜잭션 선언 방식 | 업무 로직에서 `with transaction(db_path) as conn:` | `backend/app/db.py`, `backend/app/service.py` |
| 페이징 처리 | `limit`·`offset` 쿼리 파라미터, 응답 `{total, items}` | `backend/app/repository.py` `select_run_list` |
| 데이터 접근 방식 | 연결(`conn`)을 받는 repository 함수 + sqlite3 `?`·`:이름` 바인딩 | `backend/app/repository.py` |

## 3. 프로젝트 추가 규칙

| ID | 규칙 | 이유 |
|----|------|------|
| BE-101 | 서버는 `127.0.0.1`에만 바인딩한다. 다른 주소로 열려면 대시보드 인증을 먼저 추가한다 | 대시보드에 인증이 없어 외부에서 실행 요청을 보낼 수 있다 |
| BE-102 | 실행 요청 설정의 상한 검증은 `RunOptions`(pydantic)에만 둔다. API·CLI가 같은 모델을 쓴다 | 검증이 두 곳에 있으면 한쪽만 바뀐다 |
| BE-103 | 백그라운드 실행 스레드의 최상위 처리기(`BatchRunner._run_batch_in_thread`)만 모든 예외를 잡는다 | COM-031 예외 조건. 남은 실행을 실패로 정리해야 한다 |
